# 04: 读音表与新术语

**What to build:** 有一份全频道共用的读音表（术语 → 朗读写法）。配音流水线生成朗读文本时，按读音表机械替换；旁白句如果手写了 `speech`，就以手写的为准。流水线会自动找出新术语（规则见下），列成清单。有一个命令，为每个新术语单独生成一小段试听音频。只要还有未处理的新术语，正式配音就拒绝运行。

**Blocked by:** 03

**Type:** AFK

**Status:** done

**新术语规则（2026-10-28 审查后补充）：**

1. **片段**：字幕文本里连续的英文字母、数字和 ASCII 符号。英文单词之间的单个半角空格算在同一个片段里（`KV Cache` 是一个片段）；片段和中文之间的空格不算。
2. **符号**：ASCII 可见字符里除字母、数字以外的字符（如 `+ - / # & . _ %`）。半角句读标点（`, . ! ? : ; " ' ( )`）出现在片段两端时不算进片段（`Node.js。` 里的片段是 `Node.js`）。全角中文标点永远不算。
3. **纯数字片段不算新术语**：只由数字和小数点、百分号、千分位逗号组成的片段（`30`、`3.5`、`80%`、`1,000`）。中文语境下 TTS 读数字通常没问题；读法需要特别处理的数字，在 `text` 里写成汉字，或者手写 `speech`。
4. **先扣掉读音表，再判断**：先把读音表里的键从文本中去掉（最长的键优先，区分大小写），剩下的片段才判断是不是新术语。这样 `KV Cache` 已登记时，不会再把 `KV` 报成新术语。
5. 所在旁白句手写了 `speech` 的，不检查新术语。

## Comments

- 来自 03（2026-10-28）：朗读文本目前由 `pixelbook.script.Line.spoken` 给出（有 `speech` 用 `speech`，否则用 `text`），读音替换应接在这里或流水线里调用它的地方（`pixelbook/pipeline.py` 的 `voice_episode`）。流水线的拒绝运行可以沿用 `PipelineError`，CLI 已经统一捕获它并以非零码退出。
- 来自 04 实现（2026-10-28）：自动验收项都已完成，`make check` 通过。没有改 `Status:`。
  - **接口**：`voice_episode(script_path, engine, voice, public_dir, pronunciation)` 多了读音表参数；朗读文本由 `pixelbook.pronunciation.spoken_text(line, table)` 给出（`Line.spoken` 已去掉）；新术语清单由 `find_new_terms(script, table)` 给出（术语 → 旁白句 ID 列表，按首次出现排序）。有新术语时抛 `PipelineError`，列出每个术语和所在旁白句，在生成任何配音、写任何文件之前。
  - **新术语试听命令**：`uv run pixelbook terms <script.yaml>`，用 `voice.yaml` 的默认音色，把每个新术语本身（不带上下文）读一遍，输出到 `out/terms/<术语>.wav`（每次先清空）。文件名里的 `/ \ : * ? " < > |`、空白和开头的 `.` 换成 `_`；macOS 文件名不区分大小写，所以按小写判断撞名，撞名时加 `-2`（例如 `Dry.wav`、`dry-2.wav`）。我用真实 Qwen3-TTS 跑过一次（`C++`、`Node.js`、`I/O`、`Dry`、`dry`，每段 0.6–1.3 秒，加载模型后共约 3 秒），没有听，读得对不对由你判断。
  - **对规则的解释**（票面没写明的地方）：
    - `30%` 这类带符号的数字：按例子算纯数字。纯数字的精确定义是"整数（可带千分位逗号）+ 可选小数 + 可选 `%`"，所以 `30`、`3.5`、`80%`、`1,000` 不算新术语，但 `1.2.3`（版本号）、`v2`、`3D`、`GPT-4` 算。
    - **读音表的键不匹配更长片段的一部分**：表里有 `AI` 时，`OpenAI` 不会被扣成 `Open`，而是整个 `OpenAI` 报成新术语；`C` 不匹配 `C++`，`Node` 不匹配 `Node.js`。判断方法：键的两边如果挨着字母、数字或非句读的 ASCII 符号，就不算匹配；挨着句读标点时，只有标点另一边紧跟字母或数字才不算（`Node.js` 不匹配，`DRY.`、`(DRY)`、`DRY:` 照常匹配）。替换朗读文本时用同一条规则。票面说"机械替换、先扣掉键"，没说词边界；不加边界的话，报出来的会是 `Open`、`++`、`.js` 这种看不懂的残片。
    - 扣掉的键换成一个断开符，所以键两边剩下的部分不会连成一个片段。
    - 两端句读标点会反复去掉（`(DRY),` 两端都去）；只剩标点的片段不算。
    - 替换是一次完成的：替换出来的朗读写法不会再被别的键替换。
  - **读音表格式**：键和值都必须是非空文本，空文件或 `{}` 是空表。YAML 会把 `yes`/`no`/`on`/`off` 和数字读成别的类型，这类术语要加引号，否则报错（报错信息里写了）。
  - 样例旁白稿 `books/sample/ch01/ep01/script.yaml` 只有 `DRY` 一个英文片段，在仓库的读音表下没有新术语，测试 `test_sample_book_script_is_valid` 用真实的 `pronunciation.yaml` 跑。
- 用户确认（2026-10-28）：现行规则保留。`OpenAI` 这类专有名词整个报为新术语；数字加符号（如 `30%`）算纯数字；英文加数字（如 `v2`、`GPT-4`）算新术语。
