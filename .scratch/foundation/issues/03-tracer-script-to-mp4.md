# 03: 主干：从旁白稿到 20 秒 MP4

**What to build:** 打通一条最窄但完整的路径。样例书里有一份测试旁白稿（YAML，约 6–8 个旁白句，分成 2 段、若干画面）。配音流水线逐句生成 wav，测量每句的时长，输出合成清单（ADR-0004）。Remotion 只读合成清单，由时间轴纯函数按默认停顿算出每句的起止帧（ADR-0003），每句的音频按时间轴单独放置，米白底色上的字幕框随配音逐句切换，最后渲染出 16:9 的 MP4。这一张票不做缓存、读音表、音色锁定、语音识别复核。

**Blocked by:** 01

**Type:** AFK

**Status:** ready-for-agent

- [ ] 旁白稿 schema：期 → 段（标题）→ 画面（画面说明）→ 旁白句（`id`、`text`、可选的 `speech`、`cite`）；ID 重复、`text` 超过约 20 字、缺少 `cite` 时报错，并指出具体是哪一句、哪个字段
- [ ] 配音流水线对外只有一个入口，TTS 引擎作为适配器传入：测试用假引擎（按文字长度生成确定时长的静音 wav），真实运行用 Qwen3-TTS（在 02 完成前，任选一个预设音色即可）
- [ ] 合成清单包含段、画面，以及按顺序排列的旁白句（ID、所属画面、字幕文本、音频位置、测得的时长），格式在 TS 一侧用 zod 校验
- [ ] 时间轴是纯函数：输入合成清单、停顿规则（句间 0.3 秒、换画面 0.8 秒）和帧率（30fps），输出每个旁白句、画面、段的起止帧和总帧数；秒到帧的取整规则固定
- [ ] Remotion 合成的尺寸为 1920×1080，总时长取自时间轴；不读旁白稿 YAML
- [ ] Python 测试：用假引擎跑流水线，检查合成清单的顺序、归属、时长；检查格式错误的报错信息
- [ ] TS 测试：时间轴的默认停顿、换画面停顿、总帧数，以及同样输入得到相同结果
- [ ] 用真实 TTS 渲染出一个 MP4，在 Studio 里预览时字幕随配音切换
