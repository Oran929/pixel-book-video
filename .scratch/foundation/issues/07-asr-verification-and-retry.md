# 07: 语音识别复核与重试

**What to build:** 每句配音生成后，由本地语音识别模型转回文字，与朗读文本（读音替换之后的文本，或手写的 `speech`）对比，不和字幕文本对比。对比前，两边都先用**同一个**规范化函数处理（规则见下）。差异率超过阈值就重新生成；重试几次仍然不通过，就在检查报告里标记给我。阈值和重试次数可以配置。

**Blocked by:** 04、05

**Type:** AFK（阈值、重试次数和识别模型，最后由我根据真实运行的数据确认）

**Status:** ready-for-agent

**规范化规则（2026-10-28 审查后补充）：**

1. 去掉标点和空白，统一全角和半角
2. 繁体转简体（用现成的库，如 OpenCC）。Whisper 识别中文时经常输出繁体
3. 数字统一：中文数字转成阿拉伯数字（用现成的库，如 cn2an）。两边用同一个函数处理，所以 `一步一步` 两边都会变成同一个结果，不会误报
4. 英文统一成小写（识别结果常把 `DRY` 写成 `dry` 或 `D.R.Y.`，去掉标点、转小写之后都是 `dry`）
5. 不按读音表做等价替换：对比对象已经是读音替换后的朗读文本

**重试与最终失败（2026-10-28 审查后补充）：**

- 每次重试都必须可能得到不同的音频。现在 Qwen3-TTS 每次采样本来就是随机的；如果以后在音色参数里固定了随机种子，重试时要换种子。种子不进缓存指纹（见 05）。
- 重试后通过的句子，用通过的那一版写入缓存，复核结果写进缓存旁边的 `<指纹>.json`。
- 超过重试次数仍不通过的句子：选差异率最低的那一版写入缓存，并在 `<指纹>.json` 里标记"复核未通过"。合成清单照常使用它（我可能判断"其实读对了，是识别错了"）。之后的运行直接复用，不再重试，但检查报告每次都继续列出它。想重新生成，就删掉这个缓存文件。

**识别模型：** mlx-audio（已经是项目依赖）自带 Whisper 和 Qwen3-ASR 两种语音识别模型，02 粗查时用的是 Qwen3-ASR。两种都实现成适配器，用真实运行的数据决定默认用哪个。

**验收：**

- [ ] 语音识别引擎作为适配器传入：测试用假引擎（可以设定某句返回错误文字，或者"前几次错、之后对"），真实运行用 mlx-audio 的 Whisper 或 Qwen3-ASR（配置里选）
- [ ] 阈值、重试次数、识别模型写在配置里；实现时先取一个保守的初始值，在 Comments 里写明
- [ ] 规范化规则可以测试，并且不会把格式差异误判为失败
- [ ] Python 测试，规范化的例子：`今天讀書` 与 `今天读书` 相等；`第2章` 与 `第二章` 相等；`DRY原则` 与 `d.r.y. 原则` 相等；`KV Cache` 与 `kv cache` 相等
- [ ] 复核通过的结果也缓存起来，缓存命中的句子不再重复识别
- [ ] 超过重试次数的句子出现在检查报告里，附带字幕文本、朗读文本、识别结果、差异率；再次运行时不重新生成，报告里仍然列出
- [ ] Python 测试覆盖：通过、重试后通过、最终失败（缓存了差异率最低的一版、再次运行不调用 TTS、报告仍然列出）、规范化等价
- [ ] Python 测试：手写了 `speech` 的句子（识别结果与 `speech` 一致、与字幕文本不同）能正常通过
- [ ] 人工验收：用真实识别模型（Whisper 和 Qwen3-ASR 各一遍）跑样例旁白稿，记录每句的差异率和误报、漏报情况，写进 Comments；由我据此确认阈值、重试次数和默认识别模型
