# 每期制作流水线 · Grilling 决议记录

> 日期：2026-10-27
> 来源：针对 `docs/project-plan.md` 的 grilling 讨论
> 用途：作为 `/to-spec` 的输入。请连同 `GLOSSARY.md` 和 `docs/adr/` 一起阅读，术语以 GLOSSARY 为准。
> 已写进 ADR 的决定只在这里列出编号，不重复内容。

## 1. 目标与范围

- 输入一本书的一章，产出一期或多期讲解视频：像素风、配音与画面同步、内容不超出原文。
- 第一本书：《程序员修炼之道》，EPUB 格式。之后的书优先选用 EPUB 或文字版 PDF；扫描版 PDF 暂不支持，以后需要时再加 OCR。
- 只做讲解性质的内容：用自己的话转述，尽量不用原文措辞，不超出原文的观点和事实。简介里注明书名、作者和出版社。

## 2. 期与段

- 一期的目标时长为 5 分钟，**可接受范围是 4:00–6:00**。章节过长就拆成多期，不靠压缩内容来凑时长。
- 层级：章 → 期 → 段 → 画面 → 旁白句。
- 一期分 4–6 段，每段约 1 分钟，各有一个标题。
- 段在成片中的体现：
  - **打点时间表**（必须做）：由代码根据音频算出每段的开始时间，输出 `00:00 标题` 格式的文本，发布时复制到平台的分段设置里。
  - **段标题卡**：每段开头显示，兼作转场，风格类似游戏关卡卡片（"STAGE 2：DRY 原则"）。
  - 右上角显示段进度（两个字的缩写之类）：**待定**，做外壳时再决定。

## 3. 每期流程与人工关口

1. 本地脚本把原书转换成带段落编号的 Markdown（见 ADR-0007）。
2. Claude 读完整章，产出**大纲**：拆成几期；每期分哪几段，各段的标题和预计时长；每期的核心观点清单（每条带出处）。
3. **人工关口 1**：你审大纲，约 2 分钟。
4. Claude 逐期写**旁白稿**。
5. 自动核对：先跑机械层，再跑语义层（见 ADR-0008）。
6. **人工关口 2**：你审"旁白稿 + 核对报告"，重点看被标出的句子。这时旁白稿进入定稿状态。
7. 配音：读音替换 → 新术语试听（你只听新术语）→ 逐句生成 → 语音识别复核。
8. Python 生成合成清单（见 ADR-0004）。
9. Claude 写**分镜**。
10. 在 Studio 预览，然后渲染。

人力和 token 只花在四步上：**大纲、旁白稿、分镜、语义核对**。其余步骤都是确定的脚本。

## 4. 旁白稿

- 格式为 **YAML**，按 schema 严格校验，格式不对就报错。
- 结构：段 → 画面（附画面说明）→ 旁白句。
- 每个旁白句包含：
  - `id`：稳定 ID，例如 `s03-l02`。只在创建时分配一次，永不重新编号，顺序以 YAML 中的排列为准（见 ADR-0003）。
  - `text`：字幕显示的文本，不超过约 20 个字。断句以"字幕放得下"为准，不按标点断句。
  - `speech`（可选）：朗读文本，一般由读音表自动生成。
  - `cite`：出处，例如 `ch02-¶017`。

## 5. 读音（三层）

1. **读音表**：仓库根目录的 `pronunciation.yaml`，全频道共用，内容是"术语 → 朗读写法"，由脚本机械替换。
2. **新术语检测**：脚本扫描旁白稿，找出含英文字母、数字或符号、且读音表里还没有的片段。每个新术语生成一小段试听音频，你听完后决定读法，写进读音表。人工成本只随新术语的数量增长，与句子数量无关。
3. **语音识别复核**：每句配音生成后，用本地的 MLX 版 Whisper 转回文字，与旁白句对比。差异超过阈值就自动重新生成；重试几次仍不通过，再标出来交给你处理。

## 6. 音色

- 见 ADR-0005：项目有一个默认音色，书可以覆盖，首次配音时锁定，并有守卫检查。
- 默认音色在阶段 1 通过试听选定：先用 2–3 个 CustomVoice 预设音色和 1–2 个 VoiceDesign 设计的音色，朗读同一段带术语的测试旁白（例如"DRY""正交性"），由你挑选。
- 每本书开始之前，除非你明确提出要用特殊音色，否则一律使用默认音色。

## 7. 时间轴与交接

- 见 ADR-0003（时间轴由代码计算）和 ADR-0004（合成清单）。
- 停顿的初始值：句间 0.3 秒，换画面 0.8 秒。分镜里可以对个别位置覆盖。
- 动画锚点 = 旁白句 ID + 可选偏移（秒，可以为负数）。
- 改了旁白稿之后：配音按句缓存，只重新生成改动的句子。只有增删句子时，分镜才可能需要调整。

## 8. 组件与风格

- 先完成第一期的大纲和旁白稿，再根据画面说明归纳出需要哪些组件，只做这些组件。组件库随期数逐步增长。
- 组件分两层：**通用组件**放在组件库，跨书复用，有假数据预览；**专属组件**放在所属那一期的目录，每期最多 1–2 个。专属组件第二次被别的期用到时，再升级成通用组件。
- **风格表**：调色板（约 16 色）、像素网格、像素字体、描边和阴影规则，都写成代码常量（design token），并在 Studio 里放一个"风格样张"页面。组件只能使用这些常量。
- 生图模型只用于频道形象（小人造型、整体氛围）的灵感参考，不给单个组件出参考图，也不直接拿来当素材用（生图结果的像素不对齐）。
- 频道形象要用自己的频道名、小人形象和配色，不照搬参考案例。阶段 2 做最小样片时就开始尝试，你已经有初步想法了。

## 9. 自动检查（都是确定的脚本，在阶段 1–2 与对应功能一起做）

| 类别 | 对象 | 检查内容 |
|---|---|---|
| 守卫（生成前） | 配音 | 当前算出的音色是否等于锁定音色，不一致就拒绝运行，除非加 `--revoice` |
| 质量（生成后） | 大纲 | 格式；每期预计时长在 4–6 分钟内；每条观点都有出处 |
| | 旁白稿 | 格式；出处存在；按字数估算的时长在 4–6 分钟内；每句不超过 20 字；没有读音表缺失的新术语 |
| | 配音 | 每句语音识别的差异在阈值内；总时长在 4–6 分钟内（超出时报告给你，由你决定删哪句，不自动删） |
| | 分镜 | TypeScript 类型 + zod 校验；引用的旁白句 ID 和组件名都存在 |
| | 代码 | `tsc`、lint、组件单元测试 |
| | 渲染 | 能成功渲染；成片时长等于计算出的时长 |

每项检查具体怎么实现、阈值定多少，**在实现时再和你讨论**。

## 10. 目录结构

```
pronunciation.yaml               读音表（提交）
config: 项目默认音色             （具体文件名在实现时定）
books/<书>/
  book.yaml                      书名、作者、可选的音色覆盖（提交）
  voice.lock                     锁定音色（提交）
  source.epub                    原书（不提交）
  chapters/ch02.md               转换结果（不提交）
  cache/tts/<hash>.wav           配音缓存（不提交）
  ch02/
    outline.yaml                 大纲（提交）
    ep01/
      script.yaml                旁白稿（提交）
      storyboard.json            分镜（提交）
      episode.json               合成清单（生成）
      segments.txt               打点时间表（生成）
tools/                           Python 脚本（转换、配音、校验）
video/                           Remotion 项目；渲染前由脚本把本期音频放进 public/
```

## 11. 阶段顺序（调整后）

| 阶段 | 内容 |
|---|---|
| 0 准备 | 目录结构、`.gitignore`、安装 ffmpeg（只给 Python 端用；Remotion 4 自带 ffmpeg） |
| 1 配音试验 | 试听并选定默认音色；读音表 + 新术语检测；语音识别复核；按句缓存；音色锁定守卫 |
| 2 最小样片 | 合成清单 → 时间轴计算 → 字幕同步；风格表 + 频道形象初试；中文像素字体验证；对应的自动检查 |

| 7 收尾 | README、每期制作清单 |
