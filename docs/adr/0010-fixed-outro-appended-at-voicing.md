# 固定片尾在配音时接在旁白稿后面，作为合成清单里保留 ID 的最后一段

#13 试听成片时发现视频结尾直接结束，缺少收尾（#15）。决定每期末尾加一段**固定片尾**，所有期、所有书都一样，措辞由用户定：「本期先讲到这里，欢迎大家阅读原著了解更原汁原味的内容，我们下一期见」。片尾是固定内容，不是讲解，所以不写进各期的旁白稿 `script.yaml`，没有出处，不参加照搬检查和语义核对。

片尾的文字只在 `tools/src/pixelbook/outro.py` 的 `OUTRO_LINES` 里定义，已经按每条字幕不超过 20 字、在自然停顿处断开。`pixelbook voice`（`render` 的配音一步）读完旁白稿后把它接成最后一段：段 `outro`（标题「片尾」）、画面 `outro-c01`、旁白句 `outro-l01`……。从这里起它就是普通的段：和正文一样做缺字检查、用这本书的锁定音色配音、走配音缓存和语音识别复核，字幕照常显示，时间轴、帧数核对都照常算上它。特殊处理只有两处，都按保留的段 ID `outro` 认出片尾：时长报告在时间轴导出时把总时长分成正文和片尾两部分分开写，4:00–6:00 的判断仍按含片尾的总时长；打点时间表 `segments.txt` 不列片尾，因为它每期都一样，列出来对观众没有用（#15 之后用户决定）。

这不改变 ADR-0009「画面上只常驻字幕和左上角主题」的原则：片尾不是新的画面元素，只是每期末尾多出来的几句固定旁白，显示用的还是字幕这个常驻组件。分镜可以像别的画面一样给 `outro-c01` 放组件。

## Considered Options

- **在 Remotion 里单独渲染一段片尾**（或者在时间轴末尾特殊追加）：要在合成清单之外再传一份音频和文字，时间轴、帧数核对、试听拼接都要各自特殊处理，违背「合成清单是唯一交接文件」（ADR-0004）。
- **让每期的旁白稿自己写片尾**：措辞会在各期之间走样，而且会被要求带出处、被核对，和「片尾不来自原文」矛盾。
- **片尾的文字放进配置文件**：只有一处要改、改动很少，代码常量就够了；以后要按书或按频道换片尾时再挪进配置。

## Consequences

- 旁白稿里不能用 `outro`、`outro-c01`、`outro-l01`…… 这几个 ID，用了就拒绝配音。
- 打点时间表不列片尾，最后一行仍是旁白稿的最后一段。
- `pixelbook check` 的估算时长只算旁白稿，不含片尾（片尾实际约 7–8 秒）。
