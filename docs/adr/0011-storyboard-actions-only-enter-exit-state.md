# 分镜只有入场、退场、切换状态三种动作，动画和音效都归组件

「组件与声音」阶段拷问时（2026-10-29）发现，ep01 的画面说明里有不少带变化的动作：三个方块依次落下、知识被复制到多处、改了一处另一处没改、电脑崩溃。决定分镜的触发只有三种动作：入场（enter）、退场（exit）、切换到组件自己声明的某个**状态**（state）。每个状态长什么样、每个动作怎么动、配什么音效，都在做组件时定好并绑在组件上；分镜只写在哪个旁白句、偏移几秒做哪个动作。「依次落下」写成几个组件各自入场。这样分镜保持短小，写分镜的 agent 不用编动画，分镜检查也只需要核对 ID、状态名和时间，画面效果在组件样张里一次性确认。

## Considered Options

- **组件内部自带分步动画，分镜只写「第 N 步」**：分镜更短，但每一步做什么藏在组件里，看分镜看不出画面，检查也查不到。
- **通用的移动、复制、连线动作，分镜写坐标和目标**：最灵活，但分镜会变成手写动画，agent 很难写准，也很难检查。

## Consequences

- 画面需要一种新变化时，给组件加一个状态（连同它的动画和音效），不给分镜加新动作。
- 音效默认跟着组件的动作响；分镜只能在单个触发上关掉或换掉它。
- 组件在画面上的位置用粗网格表示，箭头这类连线组件按组件 id 指向，不写坐标。
