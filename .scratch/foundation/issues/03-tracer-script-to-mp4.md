# 03: 主干：从旁白稿到 20 秒 MP4

**What to build:** 打通一条最窄但完整的路径。样例书里有一份测试旁白稿（YAML，约 6–8 个旁白句，分成 2 段、若干画面）。配音流水线逐句生成 wav，测量每句的时长，输出合成清单（ADR-0004），并把本期音频和合成清单放到 Remotion 能读取的位置。Remotion 只读合成清单，由时间轴纯函数按默认停顿算出每句的起止帧（ADR-0003），每句的音频按时间轴单独放置，米白底色上的字幕框随配音逐句切换，最后渲染出 16:9 的 MP4。这一张票不做缓存、读音表、音色锁定、语音识别复核。

**Blocked by:** 01、02

**Type:** AFK

**Status:** ready-for-agent

**交接约定（2026-10-28 审查后补充）：**

- 样例书放在 `books/sample/`，按正式结构组织：旁白稿是 `books/sample/ch01/ep01/script.yaml`，合成清单 `episode.json` 生成在同一目录。
- 本票还没有缓存：每句 wav 写到 `books/sample/cache/tts/<旁白句ID>.wav`（已被 git 忽略）；05 再改成按指纹命名。
- 合成清单里每句的音频位置，是以 `video/public/` 为起点的路径，文件名带音频内容哈希的前 8 位，例如 `episode/s01-l01-3fa2c1d9.wav`（文件名随内容变化，Studio 不会播放浏览器缓存里的旧音频）。
- 配音流水线的最后一步：清空 `video/public/episode/`，把每句 wav 按上面的文件名**复制**进去（不用符号链接），再复制一份合成清单为 `video/public/episode/episode.json`。另有一个单独的 `stage` 命令，只把期目录里的 JSON（合成清单，以后还有分镜）复制过去，供"只改了分镜、不用重新配音"时使用。谁复制：Python；Remotion 不读 `video/public/` 以外的文件。
- Remotion 在 `calculateMetadata` 里用 `fetch(staticFile("episode/episode.json"))` 读取合成清单，用 zod 校验，再由时间轴算出总帧数。不要用 `import` 直接引入生成的文件：全新克隆的仓库里 `video/public/episode/` 不存在，`make check` 也必须能通过。

**验收：**

- [x] 旁白稿 schema：期 → 段（标题）→ 画面（画面说明）→ 旁白句（`id`、`text`、可选的 `speech`、`cite`）；ID 重复、`text` 超长、缺少 `cite` 时报错，并指出具体是哪一句、哪个字段
- [x] `text` 超长的规则：去掉所有空白后，字符数超过 20 就报错；汉字、字母、数字、标点各算 1 个字符（例如 `用 KV Cache 加速` 算 10 个字符）
- [x] 配音流水线对外只有一个入口，TTS 引擎作为适配器传入：测试用假引擎（按文字长度生成确定时长的静音 wav），真实运行用 Qwen3-TTS，使用 02 定下的项目默认音色配置（`voice.yaml`）
- [x] 合成清单包含段、画面，以及按顺序排列的旁白句（ID、所属画面、字幕文本、音频位置、测得的时长），格式在 TS 一侧用 zod 校验
- [x] 时间轴是纯函数：输入合成清单、停顿规则（句间 0.3 秒、换画面 0.8 秒）和帧率（30fps），输出每个旁白句、画面、段的起止帧和总帧数。取整规则固定：每句的时长换算成帧时向上取整，保证音频不会被截断；停顿换算成帧时四舍五入
- [x] 停顿规则（默认值和取整方式）只在 TypeScript 里定义；Python 里不出现停顿秒数
- [x] Remotion 合成的尺寸为 1920×1080，总时长取自时间轴；不读旁白稿 YAML
- [x] Python 测试：用假引擎跑流水线，检查合成清单的顺序、归属、时长；检查格式错误的报错信息（包括超长规则的边界：20 个字符通过，21 个报错，空格不计）
- [x] Python 测试：流水线结束后，Remotion 静态目录（测试里用临时目录代替 `video/public/`）里只有本期的文件，合成清单里的每个音频位置都对应一个存在的文件
- [x] TS 测试：时间轴的默认停顿、换画面停顿、总帧数，以及同样输入得到相同结果
- [x] TS 测试：每个旁白句的帧数 × 帧时长（1/30 秒）不小于它的音频时长
- [ ] 人工验收：用真实 TTS 渲染出一个 MP4，在 Studio 里预览时字幕随配音切换

## Comments

- 来自 03 实现（2026-10-28）：自动验收项已完成，`make check` 通过；剩下人工验收。
  - **旁白稿 schema 比票面多了两个必填字段**：段和画面也要写 `id`（如段 `s01`、画面 `s01-c01`），和旁白句 ID 一起检查全局不重复。原因：合成清单要列出"段（ID、标题）、画面（ID、所属段）"，分镜（08）也要引用画面。报错位置写成"第 2 段第 1 个画面第 3 句（s02-l03）：`text` ……"。多余的字段（拼错的键）也报错。
  - 期目录里生成的 `episode.json` 加进了 `.gitignore`（`books/*/*/*/episode.json`），decisions.md 里它标的是"生成"。
  - 时间轴的约定：帧区间是"起含、止不含"；每句的 `endFrame` 是它音频的结束（不含之后的停顿）；画面和段从它的第一句开始，到下一个画面/段的第一句开始（中间的停顿归前一个）；总帧数 = 最后一句音频结束，末尾不加停顿。字幕用 `lineAt`：一句的字幕从它开始一直显示到下一句开始。
  - 真实运行（M5 Max，tianmei 默认音色）：`pixelbook voice` 7 句共 8 秒（含加载模型），配音 19.5 秒；渲染 673 帧 = 22.4 秒，1920×1080 / 30fps，有音频（mean -24 dB）。成片在 `out/sample-ch01-ep01.mp4`（被 git 忽略）。我抽了几帧看字幕切换正常，但没有听，也没有打开 Studio；音质和同步由你验收。
  - **人工验收步骤**（在仓库根目录）：
    ```sh
    cd tools && uv run pixelbook voice ../books/sample/ch01/ep01/script.yaml
    cd ../video && npm run studio          # 打开 Episode 合成，播放，看字幕是否随配音切换
    npm run render -- ../out/sample-ch01-ep01.mp4   # 可选：重新渲染 MP4
    ```
    如果只想看已经渲染好的成片：`open out/sample-ch01-ep01.mp4`。
