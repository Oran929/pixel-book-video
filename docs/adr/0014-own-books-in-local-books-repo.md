# 自己的书不进项目仓库，提交在 `books/` 里只在本机的书仓库

仓库要公开。以后自己做的书、做的期会发到自己的频道，不想在发布之前就出现在公开仓库里。所以项目仓库忽略整个 `books/`，公开的只有工具和一期范例 `examples/books/pragmatic-programmer/`（#68）。

但人工关口 1 和 3 是以「提交进 Git」作为审过的标记的：大纲里这一期的条目在 HEAD 里、分镜已提交且没有改动（`docs/reference/status.md`）。`books/` 被忽略以后，书里的文件就提交不了了，`status` 会一直停在关口 1。

改成：`books/` 里另有一个只在本机、不接远程的 Git 仓库，叫**书仓库**。审过的大纲、旁白稿、语义核对结果、分镜和书配置都提交在这里（`git -C books commit`）。`status` 本来就是从期目录往上找最近的 Git 仓库，所以关口的规则不用改。

## Considered Options

- **审过的标记文件**（期目录里写一份记下审过内容哈希的文件）：不依赖 Git，但 `status`、三个 skill 和 status 文档都要改；而且「审过以后又改了」这件事，Git 本来就能判断。
- **一个仓库挂公开和私有两个远程，靠分支区分**：推错一次就泄露了，每次推送都要想一下推到哪。
- **`books/` 接一个私有远程备份**：可以做，但不是必要的。本机已经有整机备份，书仓库要不要接远程由用户自己决定，代码不依赖它。

## Consequences

- `pixelbook convert` 发现 `books/` 被项目仓库忽略、自己又不是 Git 仓库时，就 `git init` 建好书仓库，并写好它的 `.gitignore`（原书、转换结果、配音缓存、产物目录）。范例和测试的临时仓库不被忽略，不会受影响。
- `status` 判断关口时看书目录所在的仓库，读音表、音色配置和显示的路径看项目仓库。书目录被所在的仓库忽略时，`status` 直接报错，不会悄悄停在关口 1。
- 范例是冻结的快照：提交在项目仓库里，`status` 照常判断；CI 对它跑不需要读原文的检查（`tools/tests/test_example.py`、`video/src/episode/example.test.ts`）。格式变了时，范例跟着改。
