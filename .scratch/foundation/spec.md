# 基础验证（阶段 0–2）：配音流水线与最小样片

Status: ready-for-agent

> 范围：项目阶段 0（准备）、阶段 1（配音试验）、阶段 2（最小样片）
> 依据：`GLOSSARY.md`、`docs/adr/0001–0008`、`.scratch/episode-pipeline/decisions.md`
> 术语一律以 GLOSSARY 为准

## Problem Statement

我想把书的一章做成像素风讲解视频，但整条流水线里有三件事最没把握，而且任何一件不成立，后面的设计都要推翻：

1. Qwen3-TTS 能不能在我的 Mac 上稳定运行，"DRY""正交性""KV Cache"这类术语能不能读对；
2. 逐句生成的配音按代码规则排进时间轴之后，听起来是否自然；
3. Remotion 能不能让字幕严格跟着配音切换，中文像素字体能不能正常显示。

在这三件事被证实之前，写外壳、做组件、写第一期旁白稿都是在沙滩上盖房子。同时，我希望从一开始就有确定的自动检查当"刹车"，而不是等到最后才补，这样后面的 AFK 工作才可信。

## Solution

用一个最小但完整的纵向切片证明"音频驱动画面"成立：

- 一份几句话的测试旁白稿（YAML），经过读音替换、逐句配音、语音识别复核，产出每句 wav 和一份合成清单；
- Remotion 读取合成清单和一份简单分镜，由代码算出时间轴，渲染出约 20 秒的 16:9 MP4：米白底色、像素字幕框随配音逐句切换、一个简单组件在指定的旁白句出现；
- 我通过试听选定项目默认音色，并对风格表和频道形象做第一次尝试；
- 每一步都带着确定的自动检查，检查不通过就不能进入下一步。

做完后，我能听到连贯的配音、看到同步的字幕，并且知道这套方案在本机可行。

## User Stories

### 阶段 0：准备

1. 作为制作者，我希望仓库有清晰的目录分层（书 → 章 → 期，原始资料与生成物分开，Python 工具和 Remotion 项目分开），这样每个文件放在哪里一目了然。
2. 作为制作者，我希望原书、转换出的全文、配音缓存、wav、mp4 都被 git 忽略，这样受版权保护的全文和大文件不会被推到 GitHub。
3. 作为制作者，我希望 Python 环境由 uv 管理、Node 依赖由 npm 管理，并且各有一条安装命令，这样换机器也能一步复原。
4. 作为制作者，我希望系统装好 ffmpeg（只给 Python 端的试听拼接和格式转换使用），这样阶段 1 的工具能够运行。
5. 作为制作者，我希望有一条命令一次跑完全部自动检查（Python 测试、TypeScript 类型检查、lint、TS 测试），这样 agent 和我都用同一个标准判断"做完了没有"。

### 阶段 1：配音

6. 作为制作者，我希望旁白稿用 YAML 编写，按"段 → 画面 → 旁白句"分层，这样既方便我审阅，也方便脚本严格处理。
7. 作为制作者，我希望旁白稿格式不对时，脚本指出具体是哪一句、哪个字段错了，这样我能马上改正。
8. 作为制作者，我希望每个旁白句都有稳定 ID、字幕文本、可选的朗读文本和出处，这样配音、字幕、核对三者都对应同一个单位。
9. 作为制作者，我希望旁白句 ID 重复、字幕文本超过约 20 字、缺少出处时，检查直接报错。
10. 作为制作者，我希望有一份全频道共用的读音表，脚本在生成朗读文本时机械地替换术语，这样同一个术语在所有期里都读得一样。
11. 作为制作者，我希望旁白句如果手写了朗读文本，就以手写的为准，不再套用读音表，这样个别特殊情况可以单独处理。
12. 作为制作者，我希望脚本自动找出含英文字母、数字或符号、但读音表里没有的片段，并列成"新术语清单"，这样我不用逐句检查。
13. 作为制作者，我希望每个新术语都能单独生成一小段试听音频，这样我只需要听这几段，就能决定读法。
14. 作为制作者，我希望在存在未处理的新术语时，正式配音拒绝运行，这样不会生成读错术语的配音。
15. 作为制作者，我希望配音逐句生成，每句一个 wav，这样改一句只影响这一句。
16. 作为制作者，我希望每句配音按"朗读文本 + 音色设置"的指纹缓存在这本书的目录下，没改动的句子直接复用，这样改稿后的重新配音只需要几秒。
17. 作为制作者，我希望删除缓存后，流水线能完整地重新生成全部配音，这样缓存永远只是加速手段，不是必需品。
18. 作为制作者，我希望每句配音生成后，都被语音识别转回文字，再和字幕文本对比，这样读错、漏读、胡乱发挥的句子都会被自动发现。
19. 作为制作者，我希望复核不通过的句子自动重新生成，重试几次仍然不通过再标记给我，这样我只需要处理少数真正有问题的句子。
20. 作为制作者，我希望识别对比时忽略标点、空格和全角/半角差异，并按读音表做等价处理，这样不会因为格式差异误报。
21. 作为制作者，我希望项目有一个默认音色配置，书的配置里可以覆盖它，这样大多数书不用单独设置。
22. 作为制作者，我希望一本书第一次配音时，脚本自动把实际使用的音色写成锁定文件，这样这本书以后不会混入别的声音。
23. 作为制作者，我希望当这本书当前算出的音色和锁定音色不一致时（包括项目默认音色被改了的情况），配音拒绝运行，并告诉我两个选项，这样我不会无意中换掉声音。
24. 作为制作者，我希望能用一个明确的参数确认"整本书重新配音"，这时锁定文件被更新，所有旧缓存不再使用。
25. 作为制作者，我希望配音完成后，脚本自动生成合成清单（按顺序列出每句的 ID、字幕文本、音频位置、时长，以及段和画面的归属），这样 Remotion 只需要读这一份文件。
26. 作为制作者，我希望合成清单里的时长由测量音频文件得出，而不是来自模型的输出，这样时间轴是确定的。
27. 作为制作者，我希望脚本报告本期配音的总时长，并按 4:00–6:00 的范围判断是否超出（样片阶段只报告、不阻止），这样以后做正式一期时能直接使用这项检查。
28. 作为制作者，我希望能用一条命令把本期配音按停顿规则拼成一条试听音轨，这样我能听整体效果，但它不是正式产物。
29. 作为制作者，我希望有一个试听对比工具：同一段带术语的测试旁白，分别用 2–3 个 CustomVoice 预设音色和 1–2 个 VoiceDesign 设计的音色生成，这样我能挑出项目默认音色。
30. 作为制作者，我希望选中的 VoiceDesign 音色能保存成参考音频，之后通过 Base 模型克隆来使用，这样音色在整个系列里保持一致。
31. 作为制作者，我希望能看到一句话的生成耗时，这样我能估计一期配音要多长时间。

### 阶段 2：最小样片

32. 作为制作者，我希望 Remotion 只读合成清单和分镜，从不直接读旁白稿 YAML，这样交接点只有一个。
33. 作为制作者，我希望分镜用 JSON 编写，只引用旁白句 ID、组件名和偏移秒数，从不写绝对时间，这样改稿重新配音后分镜不用改。
34. 作为制作者，我希望分镜引用了不存在的旁白句 ID 或组件名时，渲染前就报错，并指出具体位置。
35. 作为制作者，我希望时间轴由代码算出：每句开始时间 = 前面所有句子的时长 + 停顿；默认句间停顿 0.3 秒、换画面停顿 0.8 秒，分镜里可以对个别位置覆盖。
36. 作为制作者，我希望同样的合成清单和分镜每次都算出完全相同的时间轴。
37. 作为制作者，我希望视频总长由时间轴自动得出，不用手动填写。
38. 作为制作者，我希望动画可以锚定在"某个旁白句 + 偏移秒数"上，偏移可以是负数，这样能实现"说到一半时方块落下"或"提前出现"。
39. 作为制作者，我希望字幕框严格跟着配音逐句切换：配音开始时字幕出现，到下一句开始时切换。
40. 作为制作者，我希望画面是 16:9（1920×1080），米白底色，底部有像素风字幕框。
41. 作为制作者，我希望中文像素字体能正确显示，常用汉字不缺字，渲染后不模糊，这样就验证了字体方案可行。
42. 作为制作者，我希望有一个简单组件，在分镜指定的旁白句出现，并带有淡入或位移动画，这样能证明"组件由数据驱动、在指定时刻出现"。
43. 作为制作者，我希望有一份风格表：调色板（约 16 色）、像素网格大小、像素字体、描边和阴影规则，写成代码常量，组件只能使用这些常量，这样风格统一由代码保证。
44. 作为制作者，我希望在 Remotion Studio 里有一个"风格样张"页面，集中展示调色板、字体和描边，这样我一眼就能判断风格对不对。
45. 作为制作者，我希望在样片里试放我的频道名和小人形象的初版（可以是占位），这样能尽早看到频道形象的效果。
46. 作为制作者，我希望脚本自动输出打点时间表（`00:00 段标题` 格式），时间由时间轴算出，这样以后发布时可以直接复制。
47. 作为制作者，我希望在 Studio 里预览时，配音、字幕、组件的时间与最终渲染一致。
48. 作为制作者，我希望一条命令就能把本期音频放到 Remotion 能读到的位置并渲染出 MP4，这样不需要手动复制文件。
49. 作为制作者，我希望渲染出的 MP4 时长与计算出的时长一致（误差在一帧以内），这项检查是自动的。
50. 作为制作者，我希望最终产出一个约 20 秒的样片，能听到连贯的配音、看到同步的字幕和组件，这样就证明了"音频驱动画面"成立。

### 检查与 agent 工作方式

51. 作为执行任务的 agent，我希望测试使用假 TTS 引擎和假语音识别引擎，这样不需要加载大模型，几秒钟就能跑完，结果也确定。
52. 作为执行任务的 agent，我希望每个检查失败时都给出可以直接据此修改的信息（哪个文件、哪一句、期望什么、实际是什么）。
53. 作为制作者，我希望真实模型的效果（音质、术语读法、字体观感）由我人工验收，并在任务里明确标出来，这样 agent 不会自己判定"听起来没问题"。

## Implementation Decisions

### 总体结构

- 两个独立的部分：**Python 工具**（uv 管理）负责从旁白稿到合成清单的全部工作；**Remotion 项目**（React + TypeScript，npm 管理）负责从合成清单和分镜到 MP4 的全部工作。两者只通过合成清单交接（ADR-0004）。
- 目录按书 → 章 → 期分层；读音表和项目默认音色配置放在仓库根目录；书的配置、锁定音色、配音缓存放在书的目录里（ADR-0005）。阶段 0–2 的测试旁白稿可以放在一个专门的"样例书"目录里，按正式结构组织，这样就顺便验证了目录约定。

### 模块：配音流水线（Python，深模块）

- 对外接口只有一个：输入一期的旁白稿位置，加上可替换的 TTS 引擎和语音识别引擎；输出每句 wav、合成清单、检查报告，或者一个"拒绝运行"的结果（带原因）。
- 内部按顺序执行：旁白稿校验 → 解析书的音色（项目默认 + 书级覆盖）→ 音色锁定守卫 → 读音替换得到朗读文本 → 新术语检测 → 逐句"查缓存 / 生成 / 识别复核 / 重试" → 测量时长 → 生成合成清单 → 时长检查。
- **TTS 引擎接口**：输入朗读文本和音色设置，输出一个 wav。真实实现是在 mlx-audio 上运行 Qwen3-TTS 1.7B bf16（ADR-0002），默认使用 Base 模型加参考音频来克隆音色；CustomVoice 和 VoiceDesign 只在试听对比工具里使用。
- **语音识别引擎接口**：输入一个 wav，输出文字。真实实现是本地 MLX 版 Whisper。
- **缓存键**：朗读文本 + 规范化后的音色设置（模型标识、参考音频内容的指纹、生成参数）算出的哈希值。音色的任何变化都会自动换一个键。
- **锁定音色**：第一次正式配音时写入，内容是解析后的实际音色设置，而不是"跟随默认"这个引用。守卫负责比较；只有显式的"整本书重新配音"参数才能覆盖锁定。
- **复核对比**：先把字幕文本和识别结果都规范化（去掉标点和空白，统一全角/半角，按读音表做等价替换），再计算字符级差异率。阈值和重试次数做成可配置的值，初始值在实现时和我讨论后再定（decisions.md 第 9 节）。
- **新术语规则**：字幕文本中由英文字母、数字或符号组成的连续片段，如果不在读音表的键里，并且所在旁白句没有手写朗读文本，就算新术语。

### 模块：其他 Python 命令

- **新术语试听**：为新术语清单里的每一项生成一段短音频。
- **音色试听对比**：用同一段测试旁白，分别生成多个预设音色和设计音色的音频；能把选中的设计音色保存成参考音频，并写进项目默认音色配置。
- **试听拼接**：按与时间轴相同的停顿规则，用 ffmpeg 拼出一条试听音轨（不是正式产物）。
- 以上命令都调用同一个配音流水线模块或复用它的内部部件，不各写一套。

### 数据格式

- **旁白稿（YAML）**：一期包含若干段；每段有标题，包含若干画面；每个画面有画面说明，包含若干旁白句；每个旁白句有 `id`、`text`、可选的 `speech`、`cite`。格式由 Python 一侧的 schema 校验（ADR-0004：只有 Python 读旁白稿）。
- **合成清单（JSON）**：段列表（ID、标题），画面列表（ID、所属段），按播放顺序排列的旁白句列表（ID、所属画面、字幕文本、音频位置、时长秒数），以及生成时使用的音色指纹。格式在 Python 一侧生成，在 TypeScript 一侧用 zod 校验。
- **分镜（JSON）**：每个画面列出使用的组件和组件参数，以及若干动画触发，每个触发写"旁白句 ID + 偏移秒数 + 动作"；可以对个别位置覆盖停顿。不出现绝对时间（ADR-0003）。用 zod 校验，包括引用的旁白句 ID 和组件名是否存在。

### 模块：时间轴计算（TypeScript，纯函数，深模块）

- 输入：合成清单、分镜、停顿规则（默认句间 0.3 秒、换画面 0.8 秒，分镜覆盖优先）、帧率。
- 输出：每个旁白句、画面、段的起止帧，以及总帧数。Remotion 的总时长直接取这里的结果。
- 打点时间表也由这个结果生成。
- 秒到帧的换算规则固定（统一取整方式），保证结果确定。

### 模块：Remotion 画面

- 合成参数为 1920×1080，帧率在实现时选定（30fps 即可）。
- 每个旁白句的音频作为独立的音频片段，按时间轴放置（ADR-0003：不拼接成一条正式音轨）。
- 字幕框读取时间轴，按当前帧显示对应的旁白句。
- 组件注册表：分镜里的组件名对应到组件实现；样片阶段只需要一个简单组件。
- 风格表是一组常量（颜色、网格、字体、描边），组件只引用这些常量；另外有一个独立的风格样张合成页，只在 Studio 里预览用。
- 渲染前，脚本把本期音频复制或链接到 Remotion 能读取的静态目录。

### 自动检查

- 一条统一命令跑完全部检查：Python 测试、TypeScript 类型检查、lint、TS 测试。冒烟渲染单独一条命令（因为慢）。
- 检查失败时，输出必须指出具体位置和"期望 / 实际"的值。

## Testing Decisions

- **好的测试**只验证外部行为：给定输入文件，检查产出的文件、报告和拒绝原因，不关心内部函数怎么拆分。重构内部实现不应该导致测试失败。
- **接缝 1：配音流水线**。注入假 TTS 引擎（按文字长度生成确定时长的静音 wav）和假语音识别引擎（默认原样返回文字，可以设定某句返回错误文字，或者"前几次错、之后对"）。覆盖：
  - 旁白稿格式错误、ID 重复、超长、缺出处时报错，并指明位置；
  - 读音替换正确，手写朗读文本优先；
  - 新术语检测出来后，正式配音拒绝运行；
  - 第二次运行全部命中缓存（假 TTS 没有被调用），只改一句时只重新生成这一句；
  - 首次运行写入锁定音色；改了项目默认音色、或改了书的覆盖设置后，守卫拒绝运行；加上重新配音参数后可以通过，并更新锁定；
  - 复核失败会触发重试，超过次数后标记给人；规范化后的格式差异不算失败；
  - 合成清单的顺序、归属、时长与输入一致；
  - 总时长超出 4–6 分钟时，报告里有这一项。
- **接缝 2：时间轴计算**。纯函数测试，喂假的合成清单和分镜。覆盖：默认停顿、换画面停顿、分镜覆盖、负偏移、总帧数、同样输入结果相同、打点时间表的格式与时间；分镜引用不存在的 ID 或组件名时，zod 校验报错。
- **冒烟测试**：用一份固定的小样例真实渲染一次，检查渲染成功、MP4 时长与计算时长相差不超过一帧。不放进每次都跑的检查里。
- **人工验收（HITL）**：真实 Qwen3-TTS 的音质、术语读法、默认音色的选定、中文像素字体的显示、风格样张和频道形象的观感、20 秒样片的整体效果。
- **已有的测试先例**：仓库目前没有代码，这些测试会成为后续阶段的先例。Python 一侧使用 pytest，TypeScript 一侧选一个与 Remotion 兼容的测试运行器（例如 Vitest）。

## Out of Scope

- EPUB / PDF 转换脚本、段落编号、大纲、正式旁白稿的写作、出处的语义核对（阶段 3）。测试旁白稿里的出处只需要格式合法，不要求指向真实原文。
- 外壳：四角取景框、HUD、段标题卡、右上角段进度、转场、背景音乐、音效与混音（阶段 4）。
- 样片以外的组件库，以及通用组件与专属组件的目录约定（阶段 5）。
- 按字数估算时长的旁白稿检查、大纲检查（它们依附于阶段 3 的产物）。
- 用外部模型 API 做核对（ADR-0008：以后再说）。
- 多个音色在同一本书里混用（ADR-0005：不允许）。
