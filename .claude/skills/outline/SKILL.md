# /outline <书> <章>

参数：`$ARGUMENTS`。`<书>` 是 `books/` 下的书目录名（如 `pragmatic-programmer`）；`<章>` 是 `chNN`，只给数字时补成两位（`2` → `ch02`）。

- **输入**：转换结果 `books/<书>/chapters/chNN.md`。只读它，不读原书、不手改它。
- **输出**：`books/<书>/chNN/outline.yaml`，覆盖整章；格式和检查规则以 README「大纲」为准。
- 术语以 `GLOSSARY.md` 为准：章、单元、期、主题、段、原文、出处、大纲。

## 步骤

### 1. 准备

- 转换结果不存在时，按 README「原书转换」跑 `pixelbook convert`。
- `outline.yaml` 已经存在时，先问用户是从头重写，还是按意见修改现有大纲。

**完成**：转换结果在，并且知道是新写还是修改。

### 2. 通读整章

从第一行读到最后一行（文件长时分页读完，最后一页要看到章末脚注）。再列出单元表：

```sh
cd tools && uv run pixelbook units ../books/<书>/chapters/chNN.md
```

它给每个单元写出号、名字、首尾编号、段数和正文字数（拆期按这个字数估），下面列出单元里的提示框（`### 提示N`）和小标题（`####`）。

**完成**：读过每一个编号段落；手里有 `pixelbook units` 的单元表。

### 3. 拆期

一期 4–6 分钟，旁白按 250 字/分钟算，约 1000–1500 字；复述会压缩原文，一期大约容纳 2500 字原文正文（不算图片段，以及「相关部分」「挑战」「练习」）。

- **默认一个单元一期**。
- **短单元合并**：一个单元的核心内容讲不满 4 分钟（正文约 1500 字以下）时，和相邻单元合进一期。优先和章首导语说「紧密关联」的那个单元合并。只合并连续的单元。
- **长单元拆分**：一个单元的核心内容 6 分钟讲不完（正文约 4000 字以上，或核心观点多于 10 条）时，拆成两期，用 `{unit, from, to}` 写明各自的段落范围。切在小标题（`####`）处，每一半自成话题。合并和拆分可以同时用（短单元 + 长单元的前半），切分点选在让相关各期分量接近的地方。
- **覆盖整章**：每个单元的每个编号段落恰好属于一期：期按原文顺序排列，范围首尾相接，不留缺口、不重叠；拆分时后一半的 `from` 是前一半 `to` 的下一段，最后一半到单元最后一段（单元末尾的「相关部分」「挑战」「练习」也划进来，但不必写成观点）。章首导语和章末脚注不属于任何单元，不写进 `units`。
- **主题**：每期一个概括性主题，概括这一期覆盖的单元或范围，短到能放在画面左上角（约 12 字以内）；用原文里出现过的说法。

**完成**：每期有主题和 `units`。覆盖是否完整由第 6 步的 `pixelbook outline` 检查。

### 4. 写段和核心观点

每期：

- **段**：4–6 段，每段约 1 分钟（0.5–1.5），`minutes` 总和在 4–6 之间。段标题是这一段讲的内容，不用「开场」「总结」这类空标题；同一期里不重复。段按原文顺序推进。
- **核心观点**：这一期旁白必须讲到的内容，一般 5–10 条，每段 1–2 条，按段的顺序排列。范围内的每个提示框都要成为一条观点；其余从论证的主干里选（定义、理由、做法、反例），例子只在它承载论点时才写成观点。`id` 从 `p01` 起在整份大纲里连续编号，不在每期重新开始。

**完成**：每期 4–6 段、分钟数总和在 4–6 内；范围内的每个提示框都对应一条观点；每段至少有一条观点支撑。

### 5. 防编造

大纲是旁白稿的覆盖目标，这里编造的内容会一路传到成片。每条观点都要经得起「只看它的出处段落，能不能得出这句话」的检验。

- **只来自原文**：观点只能复述、压缩原文，不加书里没有的例子、数据、结论或评价，也不用对英文原版、其他版本或书外知识的了解来补充。
- **每条都有出处**：`cite` 列出支撑这句话的全部段落，不多列：一句话概括了几段时就列几段。出处里至少有一个文字段，图片段（`[图 …]`）只能和文字段一起列。出处落在本期的单元或范围之内。章末脚注不属于任何单元，只在它的标记所在的段落或标题（如 `### 提示24　…[18]`）落在本期范围内时才列。
- **用自己的话**：观点、主题、段标题都改写原文，不照搬整句；提示框标题（`提示N` 后面的部分）、术语和专有名词（ETC、DRY、曳光弹）照用。主题、段标题和观点 `text` 不写「提示14」这样的编号：编号对观众没有意义，旁白稿也不念（`pixelbook outline` 和 `pixelbook check` 都会报错）。
- **只用书里的术语**：主题和段标题里的概念、名字都在本章原文里出现过。

**完成**：逐条重读每个观点和它出处里的每个段落，删掉或改掉所有出处推不出的说法。

### 6. 写文件，跑检查

写 `books/<书>/chNN/outline.yaml`（`chapter` 是章号整数），然后：

```sh
cd tools && uv run pixelbook outline ../books/<书>/chNN/outline.yaml
```

按报错修改，再跑，直到退出码 0。只改大纲，不改检查。覆盖整章、出处落在本期范围内（含脚注规则）、不只引用图片段都由这条命令检查，不另写脚本自查。

命令列出的「疑似照搬原文」警告不影响退出码：逐条看，是术语、专有名词、提示框标题就保留，否则改写那条观点。

**完成**：`pixelbook outline` 退出码 0，每条照搬警告都看过。

### 7. 交给用户（人工关口 1）

用中文汇报，然后停下等用户审。大纲不提交；用户确认通过后才提交。

- 拆成几期，以及拆分理由：哪些单元合并、哪些拆开、切在哪个小标题，为什么。
- 每期一节：`id` 和主题；覆盖的单元或段落范围；各段标题和分钟数（附总时长）；观点条数。
- 需要用户拍板的取舍：没写成观点的重要内容、拿不准的切分点、可能偏离原文的观点。

用户提的修改意见如果是规则问题（拆期、观点怎么选、措辞），先改这份 skill，再按改过的 skill 改大纲。
