# /storyboard <期目录>

参数：`$ARGUMENTS`，形如 `books/<书>/chNN/epNN`。

- **输入**：`<期目录>/script.yaml`（`status: final`）的画面说明 `description` 和旁白句；README「分镜」（连同它下面的网格、字宽估算、嵌套、带序号的状态、显示文字、音效、配乐各小节）和「组件目录」。组件只从这两节了解，它们写全了参数、占几格、状态、动画和音效。
- **输出**：`<期目录>/storyboard.json`、`pixelbook render` 出的 MP4，和交给用户的「表现不了」清单。格式和全部机械规则以 README「分镜」为准，由 `npm run timeline` 判定；这份 skill 只管选组件、摆位置、挂触发。
- 术语以 `GLOSSARY.md` 为准：期、画面、旁白句、分镜、组件、触发、状态、配乐、合成清单、时间轴。

## 边界

- **旁白稿是定稿，只读不改**：画面说明、旁白句、出处、`status` 都保持原样。配音和出处都由它定，用户在关口 3 提的意见也只落到分镜（或组件）上。
- **只用现有组件**：只用组件目录里的组件，以及它们声明过的状态、动画和音效。画面说明里组件表现不了的部分，记进「表现不了」清单交给用户，由用户决定是改画面说明还是新做组件。
- **显示文字只出自本画面**：组件上的每一段字（知识块 `label`、提示牌的 `label`、`number`、`title`，电脑的 `screen`）都取本画面画面说明或某个旁白句原句里的字，口径见 README「显示文字」。提示牌的 `title` 也照这条取：原书提示框的标题只有出现在画面说明或旁白句里时才能用。
- 票的状态（GitHub issue 的标签、开关）保持原样。

## 步骤

### 1. 准备

```sh
cd tools && uv run pixelbook check ../<期目录>/script.yaml
```

`script.yaml` 里不是 `status: final`，或检查退出码不是 0 时，停下告诉用户：分镜只按审过的定稿写（关口 2）。

`storyboard.json` 已经有 `scenes` 时，先问用户是从头重写，还是按意见修改现有分镜。从头重写时保留顶层的 `music`（换曲由用户决定）。

然后配音，写出合成清单 `episode.json`（缓存命中时不重新生成），时间轴导出要用它：

```sh
uv run pixelbook voice ../<期目录>/script.yaml
```

**完成**：旁白稿是定稿且检查通过；`<期目录>/episode.json` 是这次配音写出的；知道是新写还是修改。

### 2. 选配乐

```sh
cd video && npm run music:pick -- ../<期目录>
```

命令按 README「配乐 › 选曲」选一首写进 `storyboard.json`（还没有分镜时写一份只有 `music` 的骨架），已经有 `music` 时原样保留。配乐以它的结果为准：随机由命令完成，`music` 字段之后不再改。记下它打印的曲子、许可和是否要署名，交给用户时用。

**完成**：`storyboard.json` 里有命令写的 `music`。

### 3. 读

读 README「分镜」全节和「组件目录」全节；再读 `script.yaml` 里每个画面的画面说明和它的每个旁白句。

**完成**：每个画面都知道画面说明要表现什么、旁白在哪一句讲到它。

### 4. 写分镜

在 `storyboard.json` 里给**每个**画面写一项（合成清单里的画面一个不落，每项至少一个组件；片尾不是画面，不写），保留 `music`：

- **落到组件上**：画面说明里的每个东西、每个变化，都找一个组件和它的状态、动作来表现。画面说明有几部分时，每一部分都要有着落；组件表现不了的部分（缺这样的组件、状态或动作），这个画面照样用能表现的组件写，把那部分记进「表现不了」清单：画面 ID、画面说明里的那段话、缺的是什么。
- **触发挂在旁白上**：组件在旁白讲到它的那一句入场或切换状态，`line` 用本画面的旁白句，`offset` 按句子里讲到它的位置估秒数。画面一开始就要有的写本画面第一句、`offset: 0`（第一句上不能用负偏移）。
- **接到下一个画面**：同一个东西要留到下一个画面时，本画面不写它的 `exit`，下一个画面里再放一个同样参数、同样位置的组件，在第一句 `offset: 0` 用 `animation: "none"` 入场，看起来就是没动。
- **摆放**：按「网格」写 `at`，同时在画面上的组件格子错开；嵌套按「嵌套」写 `parent`，箭头按「组件目录 › 箭头」写 `from`、`to`，两端之间留出空档（检查不查箭杆是否穿过别的组件）。
- `pauses` 只在画面需要多停一会儿（比如等一个动画播完）时写。

**完成**：每个画面都有一项、至少一个组件；每个画面说明的每一部分要么有组件表现，要么在「表现不了」清单里。

### 5. 检查

```sh
cd video && npm run timeline -- ../<期目录>
```

按报错改分镜再跑，直到退出码 0。报错写明第几个画面、第几个组件或触发、哪个字段；只改分镜，修法按 README「分镜」的对应规则来。

**完成**：退出码 0。

### 6. 出片和看样帧

```sh
cd tools && uv run pixelbook render ../<期目录>/script.yaml
```

失败时按它报的那一步处理：分镜问题回到第 4 步，其他问题停下告诉用户。

出片后看样帧：对每个画面，至少在所有组件都入场之后取一帧（帧号 = `timeline.json` 里画面的 `startFrame` 加上组件入场的帧数，`timeline.json` 已经算上片头），

```sh
cd video && npx remotion still Episode <scratchpad>/<画面 ID>.png --frame=<帧号>
```

用 Read 打开图片看：组件压住字幕、箭头穿过别的组件、字挤出框，回到第 4 步改位置再从第 5 步跑起。

**完成**：`render` 退出码 0；每个画面的样帧都看过，没有遮挡和穿过。

### 7. 交给用户（人工关口 3）

用中文汇报，然后停下等用户看 MP4。分镜先不提交。

- **置顶**：「表现不了」清单（画面 ID、画面说明里的那段话、缺的组件或状态）；没有时写「没有」。
- MP4 路径，`render` 汇总里的总时长（片头、正文、片尾）和 4:00–6:00 的判断、复核未通过的句子。
- 配乐：曲子 ID、曲名、作者、许可，避开了哪一期的哪首；要署名时附上 `credits.txt` 的路径。
- 每个画面用了哪些组件，一行一个画面。

用户的意见只改分镜（或用户同意的组件改动），改完从第 5 步跑起，再回到这一步。用户的意见如果是规则问题（怎么选组件、怎么摆、触发怎么挂），先改这份 skill，再按改过的 skill 改分镜。用户说通过时，提交 `storyboard.json`。
