# 防编造核对分两层：先跑确定的脚本，再由独立的 subagent 做语义判断

视频只做讲解，内容不能超出原文的观点和事实，并且尽量不照搬原文措辞。机械层由脚本检查：每个旁白句都有出处、出处编号确实存在、大纲里的每条核心观点都被旁白覆盖。机械层通过后，再进行语义层核对：由一个独立的 Claude Code subagent 只看"旁白句 + 它引用的原文段落"，逐句判定"支持 / 部分支持 / 不支持"。核对不能交给写稿的那个上下文，因为它倾向于认为自己写的是对的。你审稿时看到的是"旁白稿 + 核对报告"。

## Considered Options

- **由脚本调用外部模型 API 来核对**：可以完全自动化，可以强制输出结构化结果，还可以换一家模型、真正"换一双眼睛"，但要按 token 另外付费，也要额外搭建。等核对流程稳定、对质量有了清晰的把握之后，再换成这种方式；这样也方便以后让项目不只绑定 Claude。
