# 04: 读音表与新术语

**What to build:** 有一份全频道共用的读音表（术语 → 朗读写法）。配音流水线生成朗读文本时，按读音表机械替换；旁白句如果手写了 `speech`，就以手写的为准。流水线会自动找出新术语（规则见下），列成清单。有一个命令，为每个新术语单独生成一小段试听音频。只要还有未处理的新术语，正式配音就拒绝运行。

**Blocked by:** 03

**Type:** AFK

**Status:** ready-for-agent

**新术语规则（2026-10-28 审查后补充）：**

1. **片段**：字幕文本里连续的英文字母、数字和 ASCII 符号。英文单词之间的单个半角空格算在同一个片段里（`KV Cache` 是一个片段）；片段和中文之间的空格不算。
2. **符号**：ASCII 可见字符里除字母、数字以外的字符（如 `+ - / # & . _ %`）。半角句读标点（`, . ! ? : ; " ' ( )`）出现在片段两端时不算进片段（`Node.js。` 里的片段是 `Node.js`）。全角中文标点永远不算。
3. **纯数字片段不算新术语**：只由数字和小数点、百分号、千分位逗号组成的片段（`30`、`3.5`、`80%`、`1,000`）。中文语境下 TTS 读数字通常没问题；读法需要特别处理的数字，在 `text` 里写成汉字，或者手写 `speech`。
4. **先扣掉读音表，再判断**：先把读音表里的键从文本中去掉（最长的键优先，区分大小写），剩下的片段才判断是不是新术语。这样 `KV Cache` 已登记时，不会再把 `KV` 报成新术语。
5. 所在旁白句手写了 `speech` 的，不检查新术语。

**验收：**

- [ ] 读音表 `pronunciation.yaml` 放在仓库根目录。02 的试听结论是没有读错的术语，所以初始条目是两个原样不变的已确认条目：`DRY: DRY`、`KV Cache: KV Cache`
- [ ] 替换结果确定，长术语优先匹配（例如 "KV Cache" 先于 "KV"），区分大小写
- [ ] 手写的 `speech` 优先，不套用读音表
- [ ] 读音表允许写原样不变的条目（例如 `DRY: DRY`），表示"已确认，读法不变"；这类术语不算新术语
- [ ] 新术语清单报告每个术语出现在哪些旁白句
- [ ] 新术语试听命令为每个术语生成一段音频，文件名能看出是哪个术语（文件名里不能用的字符，如 `/`，要替换掉）；暂时使用项目默认音色（06 完成后改用书解析出的音色）
- [ ] 有新术语时，流水线返回"拒绝运行"并列出这些术语，不生成任何配音
- [ ] Python 测试覆盖：替换、长词优先、手写优先、新术语检测、拒绝运行
- [ ] Python 测试：读音表里有原样不变的条目时，该术语不出现在新术语清单里，朗读文本保持原样
- [ ] Python 测试，用下面的例子把规则走一遍（读音表只有 `DRY`、`KV Cache` 两条）：
  - `用 KV Cache 加速` → 没有新术语
  - `KV 和 Cache 分开写` → 新术语 `KV`、`Cache`
  - `C++ 和 Node.js。` → 新术语 `C++`、`Node.js`
  - `性能提升 30%，第 2 章` → 没有新术语
  - `I/O 很慢` → 新术语 `I/O`
  - `dry 小写` → 新术语 `dry`（区分大小写）
