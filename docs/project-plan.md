# 像素风书籍讲解视频 · 项目方案

> 最后更新：2026-10-27
> 状态：技术方案已定，准备进入阶段 0

## 1. 项目目标

**一句话目标**：输入一本书的一章，输出一个 5 分钟左右、像素风、配音和画面同步、内容不编造的讲解视频。

**参考案例**：抖音 @小白debug 讲 vLLM 显存池的视频。

| 要素 | 观察 | 对应做法 |
|---|---|---|
| 画风 | 像素风，米白底色，四角取景框，右上角 HUD（生命值 + 频道名） | 固定模板，每期只换内容 |
| 元素 | 像素小人、显卡、显存池、方块、请求卡片、成就弹窗 | 可复用的组件库 |
| 动画 | 位移、缩放、淡入淡出、少量浮动粒子 | 简单动画，成本低 |
| 字幕 | 底部像素风对话框，逐句切换，与配音同步 | 字幕时间轴由配音生成 |
| 节奏 | 约 2–3 秒一句，一个画面 3–5 句 | 5 分钟约 25–35 个画面 |

核心思路：**固定模板 + 少量组件 + 配音驱动时间轴**。

## 2. 技术方案（已定）

| 层 | 选择 | 说明 |
|---|---|---|
| 框架 | **Remotion**（React + TypeScript） | 代码生成视频，本机渲染 |
| 配音 | **Qwen3-TTS 1.7B bf16**，通过 mlx-audio 在本机运行 | 离线、免费、Apache 2.0 可商用 |
| 背景音乐 | **OpenGameArt 上的 CC0 8-bit 循环曲**，2–3 首共用 | 零成本、零版权风险 |
| 音效 | **jsfxr** 自己生成 5–8 个 | 风格与像素画面统一 |
| 运行环境 / 依赖 | Node.js、npm、ffmpeg、Python（uv 管理） | 见第 3 节 |

### 2.1 框架：Remotion

- **Remotion 是什么**：不是独立软件，而是一个代码库（npm 包）+ 命令行工具 + 浏览器里的预览界面（Remotion Studio）。
- **React 和 TypeScript 的关系**：不是二选一。React 是 Remotion 描述画面的方式（必须用）；TypeScript 是编程语言（JavaScript 加类型检查）。选择 **React + TypeScript**。
- **选 TypeScript 的理由**：
  - Remotion 官方模板默认用 TypeScript，资料最多
  - 可以给"剧本 JSON"定义格式，AI 生成的数据有错时，渲染前就能发现
  - 不影响最终画面质量
- **许可**：个人和不超过 3 人的公司免费，允许商用。

**考虑过的替代方案**

| 框架 | 不选的原因 |
|---|---|
| Motion Canvas | 真开源、动画更细腻，但命令式写法不适合"JSON 驱动"，画 UI 要自己在 canvas 里画 |
| Revideo | Motion Canvas 的分支，面向自动化，但社区小、资料少 |
| Manim | Python，擅长数学公式，不适合像素风 UI |

选 Remotion 的理由：数据驱动最顺手；对话框、HUD 等像素 UI 直接用 CSS 实现；官方提供 AI agent skill，支持在 Studio 里预览编辑。

### 2.2 配音：Qwen3-TTS

- **模型大小**：1.7B（比 0.6B 效果更好；MLX 下约占 4.5 GB 内存，M5 Max 完全够用；离线生成，不在乎速度）
- **精度**：bf16（原始精度，不用 8bit/4bit 压缩版）
- **模型类型与用法**：
  - **CustomVoice**：内置预设音色（Vivian、Serena、Dylan、Uncle_Fu 等）
  - **VoiceDesign**：用文字描述生成新音色
  - **Base**：用参考音频克隆音色
  - **推荐流程**：先用 VoiceDesign 设计出满意的"频道声音"并保存参考音频 → 之后每章用 Base 克隆，保证系列声音一致。若某个预设音色已经满意，直接用 CustomVoice。
- **模型示例**：`mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16`
- **时间戳方案**：逐句生成音频，再拼接；每句的开始和结束时间由音频时长直接算出，精确且不依赖模型输出时间戳。

**考虑过的替代方案**

| 方案 | 不选的原因 |
|---|---|
| edge-tts | 零配置，但需联网，且非微软官方开放接口，存在被限制和商用灰色地带的风险 |
| IndexTTS2 | 情感表现和时长控制强，但主要面向 NVIDIA 显卡，Mac 上部署麻烦 |
| CosyVoice 3 | 效果好，同样偏向 NVIDIA 环境 |

### 2.3 配乐与音效

- **背景音乐**：优先选 **CC0**（公有领域，不用署名）。若用 **CC-BY-SA**，需在视频简介署名作者，衍生作品同样许可。Pixabay Music 可作补充，下载前确认许可。
- **音效**：用 jsfxr 生成方块落下、弹出、成就解锁等 8-bit 音效。
- **混音**：有人说话时自动压低背景音乐。
- **AI 生成音乐**：暂不使用。以后想要专属主题曲时可试 ACE-Step 1.5（可商用）或 Stable Audio 3.0（年收入 100 万美元以下可商用），需先验证在 Mac 上的运行情况。

## 4. 数据流

```
原文 ─[Claude]─► 旁白稿 + 出处台账 ─[你审稿]─► 定稿
定稿 ─[Python: Qwen3-TTS]─► 每句 wav + 时长表
定稿 + 时长表 ─[Claude]─► 分镜 JSON
分镜 JSON + 音频 ─[Remotion]─► Studio 预览 ─► MP4
```

Remotion 只负责最后一段，前面的文字、配音、分镜都是普通文件。

## 5. 搭建阶段（按风险排序）

**最没把握的三件事（最先验证）**

1. Qwen3-TTS 在本机能否顺利运行，速度如何，"vLLM""KV Cache"等术语读得是否准确
2. 逐句生成的音频拼接后是否自然（句间停顿）
3. Remotion 里音频与字幕能否严格对齐，中文像素字体能否正常显示

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| 0 准备 | 建仓库和文件夹结构、`.gitignore`、一行 README；安装 ffmpeg | 仓库建好，第一次提交完成 |
| 1 配音试验 | 只用 Python：3–5 句测试旁白 → 逐句 wav → 拼接 → 时长表 | 能听到连贯配音，并得到每句起止时间的 JSON |
| 2 最小样片 | Remotion 中只做米白底色 + 字幕框 + 一个简单组件，读取阶段 1 的音频和时长表 | 渲染出约 20 秒 MP4，字幕随配音切换，组件在指定句子出现 |
| 3 外壳模板 | 四角取景框、HUD、讲解小人头像、成就弹窗、转场、配乐与音效混音 | 外壳在 Studio 中预览正常 |
| 4 组件库 | 逐个做 10–15 个通用组件，每个用假数据在 Studio 中确认 | 组件可由 JSON 驱动 |
| 5 第一章 | 完整走一遍每章流程，根据问题回头调整 | 第一章成片 |
| 6 收尾 | 完善 README（运行方式、踩过的坑），给成片打 tag，整理"每章制作清单" | 清单可复用 |

**排序理由**

- 阶段 1 不碰 Remotion：配音有问题能尽早换方案
- 阶段 2 先于模板和组件：先证明"音频驱动画面"成立，再做好看的东西
- 组件库放后面：工作量最大但最确定

## 6. 每章制作流程

1. **提取原文，写旁白稿**：约 1200 字（中文每分钟约 250 字）。每句旁白标注原文出处（段落或页码）。
2. **你审稿**：只看"旁白 + 出处 + 画面说明"的文字稿。这是改动成本最低的检查点。
3. **生成配音**：逐句生成，得到音频和时长表，音频放入 Remotion 项目的 `public/`。
4. **写分镜 JSON**：每个画面用哪个组件、第几句触发什么动画。通用组件不够用时，每章最多新做 1–2 个专属组件。
5. **Studio 预览**：`npx remotion studio`，视频总长由音频长度自动计算。发现问题改 JSON。
6. **渲染**：`npx remotion render`，本机输出 MP4，同时混入配乐和音效。

**防编造规则**

- 旁白只能复述、压缩或引用原文，不加书里没有的例子、数据和结论
- 画面标签只用书中出现过的术语；比喻只表现原文已有的逻辑
- 写完后逐句核对出处，并对照"本章核心观点清单"逐条打勾

**顺序要点**：文字定稿 → 配音 → 分镜。旁白一改，配音和分镜都要重做。

## 7. 成本控制

1. 模板只做一次，之后每章只产出剧本数据
2. 不逐帧检查画面，视觉检查交给 Studio 预览
3. 先审文字，再做动画
4. 渲染、配音、配乐都在本地或免费
5. 一章一次会话，上下文只放本章原文和模板说明

粗略估计：首次搭模板约相当于 2–3 章的工作量，之后每章是一次中等规模任务。
